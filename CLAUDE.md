# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The app is called **Kao (ก้าว)** — display name only. Internal ids stay `exercise-plan` on purpose (Android appId, IndexedDB db name, backup `app` field, `exercise-plan.apk` release asset the in-app updater looks for, service-worker cache); renaming them would break updates or existing data.

A personal, Thai-language workout + nutrition planner (Vite + React 19 + TypeScript + Tailwind CSS v4, no router, `lucide-react` icons, Leaflet/OpenStreetMap for run maps). It's a static SPA deployed to Vercel (`vercel.json`, output `dist/`). Auth and cross-device sync use Supabase (Google + email/password); login is optional — "local mode" (`src/lib/localMode.ts`, device flag `localMode` in localStorage) keeps everything on the device, and logging in later merges it up (first login on a device without an `owner` key).

Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` in `.env.local` (see `.env.example`) and in Vercel project env vars. `src/lib/supabase.ts` throws at startup if missing.

The owner: male, 20 y/o, 165 cm, 64.5 kg, currently jogs 2.5–5 km 2–3×/week, lives in Thailand, goal is a lean athletic "Tom Holland" physique, trains at a gym or a public park. These are the defaults in `src/lib/calc.ts`.

## Commands

- `npm run dev` — dev server
- `npm run build` — `tsc -b` type-check then `vite build`
- `npm test` — vitest (`src/lib/__tests__/`); single file: `npx vitest run src/lib/__tests__/programs.test.ts`. Tests cover pure logic only (calc, programs safety properties like ≤20% weekly volume jumps and taper, progression, pace, GPX parsing, merge, dates).
- `npm run lint` — oxlint
- `npm run e2e` — Playwright E2E (`e2e/*.e2e.ts`; named `.e2e.ts` so vitest doesn't pick them up). It builds with `--mode e2e`, serves `vite preview` on 4173 and drives the app in local (no-login) mode, seeding data via `seed()` in `e2e/helpers.ts` (localStorage → migrated to IndexedDB on load) and reading it back with `idb()`. Uses the installed Google Chrome locally, Playwright's Chromium in CI. Single test: `npx playwright test -g "<name>"`.
- CI: `.github/workflows/ci.yml` runs lint, unit tests, build and E2E on every push/PR to main (dummy Supabase env).

## Android app (Capacitor)

`android/` is a Capacitor 8 project (`capacitor.config.ts`, appId `com.synxdicate.exerciseplan`) wrapping the same `dist/` build for personal sideloading. `npm run android:apk` builds web + syncs + `gradlew assembleDebug` (needs JDK 21 and an Android SDK with `ANDROID_HOME` set); `npm run android:install` installs via adb. `src/lib/native.ts` exposes `isNative`, `SITE_URL` (email links must point to the Vercel site, not `https://localhost`) and the `BackgroundGeolocation` plugin; `useRunTracker` uses it on native so GPS keeps recording with the screen off (foreground-service notification), and skips the web screen-off gap logic. Google sign-in on native opens a Chrome Custom Tab (`src/lib/nativeAuth.ts`) and returns via the deep link `com.synxdicate.exerciseplan://login-callback` (intent-filter in `AndroidManifest.xml`; must also be in Supabase Auth → Redirect URLs); the native Supabase client uses PKCE, the web keeps implicit flow. The service worker is only registered on the web. Portrait is locked (manifest `screenOrientation` + PWA `orientation`). Safe areas use `--sat`/`--sab` (max of `env()` and Capacitor's `--safe-area-inset-*`).

Run share image: `src/lib/shareImage.ts` draws a 1080×1350 canvas — style `card` (gradient) or `white`/`black` transparent PNG stickers with a soft shadow for overlaying on the user's own photos — (route via `projectRoute` in `geo.ts`, fixed brand colors since it's exported); native writes it to the cache dir with `@capacitor/filesystem` and opens the Android share sheet via `@capacitor/share`, web uses Web Share with files or downloads. "บันทึกรูป" (`saveImage`) uses `@capacitor-community/media` on native to save the PNG (transparency kept) into an app album `Exercise-Plan` (no storage permission needed), and downloads on the web. The chosen style is remembered in device key `shareStyle` (default transparent white). Native-only extras: `src/lib/notify.ts` (local notifications: rest-timer end while the screen is off — needs `USE_EXACT_ALARM` — and 14 days of daily plan reminders scheduled by `useReminderSchedule` in `src/lib/reminders.ts`, setting in the avatar menu), `src/lib/voice.ts` (Thai TTS per-km cues fired from the GPS callback via `useRunTracker({ onSplit })`, so they work with the screen off). `src/lib/update.ts` (native only) checks the latest GitHub Release (`Synxdicate/exercise_plan`, public) for an `exercise-plan.apk` asset newer than `APP_VERSION` (`semver.ts`) and shows a banner whose button opens `releases/latest/download/exercise-plan.apk`. Publishing: tag the version, then `npm run android:release` (`scripts/release-android.sh`: vite build → cap sync → `assembleRelease` signed via the git-ignored `android/keystore.properties` → `gh release create/upload`). The release key is a copy of the machine's debug key (`~/.android/exercise-plan-release.keystore`) so release APKs install over the earlier debug installs without losing data — back it up. `npm run android:update` still installs a debug build over USB. App icon/splash sources are in `assets/` (white Lucide footprints on #e11d48 — "ก้าว" — rendered via headless Chrome; `public/favicon.svg` and the in-app logo use the same glyph); Android resources were generated from them with PIL (night splash folders must be named `drawable-land-night-*`, orientation before night).

## Architecture

- `src/data/*.ts` holds **all content** (exercises, weekly schedules, foods, YouTube channels, references). Components only render it. Content edits go here, not in components.
  - `workouts.ts`: `gymWeek` and `parkWeek` are parallel 7-day `Day[]` arrays (shared run/rest days). `phases` describes the 12-week periodization (week 9 = deload, handled specially in `Plan.tsx`). Each exercise's `video` field is a YouTube *search query*, turned into a link via `yt()`.
  - `nutrition.ts`: approximate kcal/protein values (USDA / labels / commonly published Thai single-dish values).
  - `sources.ts`: YouTube channels and research references shown on the Sources tab.
- `src/lib/calc.ts`: Mifflin-St Jeor BMR × activity → TDEE, plus goal delta → macro targets (protein 2.0 g/kg, or 1.8 on lean bulk; fat 0.9 g/kg; carbs fill the rest). Shared by Overview and Nutrition tabs via the `profile` state in `App.tsx`.
- Programs: `src/data/programs.ts` defines `physique` (12 wk, reuses `gymWeek`/`parkWeek`), `base` (ongoing, no race: a 4-week cycle chosen from the calendar week since `CYCLE_EPOCH`; its done-ids use the real Monday date instead of the week number so a new cycle starts unticked), `five` (5K speed, 8 wk), `mini` (10-week beginner 10.5 km race program, `miniWeeks` in `programs.ts`: 3 runs + 2 light strength, run-walk easy/long runs with `guides.runWalk` until week 8, km targets so the shared race-program tests apply; readiness = walk-jog ≥4 km via `Capacity.anyKm`), `start` (9-week run-walk for beginners, Couch-to-5K style: `startWeeks` in minutes, 3 run-walk days with a time-based `guide` — walk warm-up/cool-down, `work`/`recover` steps without `pace` so the pace coach stays quiet — no `targetKm`, so UI shows `duration` instead; 2 light strength days; tests cap per-session run time growth), `strength` (strength-only ongoing 4-week cycle: physique's 3 strength days + `lowerB`, week 4 halves sets, no runs, `weekKm` 0), `ten` (10K, 12 wk), `half` (16 wk) and `full` (18 wk). `isRace` = the program has `raceKm`. Race programs are generated per week from the `tenWeeks`/`halfWeeks`/`fullWeeks` tables (`easyB: 0` turns Saturday into a rest day) (easy/quality/easy/long km, cutbacks, taper) plus 2 runner strength days per mode (hip abduction + soleus calf raise; Pogo Jumps added to day A from week 4, not in taper). Tests enforce: ≤20% weekly km jumps, ≤1 hard run/week, taper, and no single run longer than 110% of the longest run in the previous 30 days except race day (Frandsen 2025), starting from each program's stated entry long run (base/ten 5 km, half 7, full 18). `useProgram()` (`src/lib/program.ts`) is the single source for the current program, mode, week and plan; with a `raceDate` the current week is computed backwards from race week; otherwise from the synced `programStart` Monday (set by `setProgram`/`setWeek`; old data without it derives the start from the `week` key), so weeks advance with the calendar. The plan tab's week pills only change the viewed week; "ทำสัปดาห์ X ซ้ำ / ข้ามไปสัปดาห์ X" calls `setWeek`. Gym vs park is chosen per weekday slot: the `mode` key holds the preference (`gym`/`park`/`mix` — mix sends the week's last strength day to the park), `dayLocation` holds per-day overrides, and `weekPlan` swaps in the matching variant (`variants()` returns gym/park 7-day arrays with identical run/rest days). A day also counts as done when a matching log exists that date (`useDayDone` in `src/lib/dayDone.ts`: run day + run, strength day + session; an explicit untick wins). Check-offs use slot ids `${program}-w${week}-d${i}` (i = 0 Monday) so switching location keeps them; `isDone` also reads the older mode+key ids.
- Program fit: `src/lib/programFit.ts` (pure, tested) — `capacity` = longest real run (pace ≤10:00/km) in 60 days by km and minutes, `NEEDS` per program (start/strength none, physique 20 min, ten 30 min, base/five 5 km, half 7 km, full 18 km), `recommended` = furthest ready step on `PATH` (start → ten → half → full), `nextStep` (start → ten once ready; non-ongoing programs at their last week). `ProgramPicker` (shared by `ProgramSheet` and onboarding) shows the path + other programs with ready/recommended labels; `NextStepCard` (home + plan, dismiss key `nextStepSeen`). Home shows only today's things; the weekly body map is `WeeklyMuscles` in the plan tab, the profile/BMR card is `ProfileCard` in the food tab.
- Exercise swaps/additions: `src/data/library.ts` groups exercises by movement pattern (same primary muscles) and holds muscles for exercises not in `muscles.ts` (`musclesOf` falls back to it). `useProgram().plan()` runs `applyCustom`: synced key `exerciseSwaps` (original name → replacement, applies to every day; keeps the original sets/reps/rest unless the unit differs, sets `swappedFrom`) — a swap whose replacement is gym-only (`where: 'gym'` in `library.ts`) is skipped on park days (a test asserts no park day contains a gym-only exercise) and `extraExercises` (keyed `${program}:${day.key}:${location}`, marked `added`). A new strength exercise in `workouts.ts` should also get a library entry (test enforces it). Solo mode (synced `soloMode`, toggle on gym strength days) makes `applyCustom` swap lifts in `needsSpotter` (`library.ts`: bench → DB bench, back squat → leg press, front squat → goblet) unless the user swapped them; those exercises get `solo: true`.
- `src/lib/progression.ts` `suggest()` implements double progression for the workout player (all sets at the top of the rep range → +2.5 kg, +5 kg for lower-body lifts). References in `src/data/sources.ts` carry a category and evidence `level`; claims shown in the app should map to one of them (PubMed links were verified via eutils), and media sources are only for describing Tom Holland's training style.
- Forms: use `TextInput` / `NumberInput` (unit suffix, optional `stepper`) / `SelectInput` / `DateInput` from `src/components/Form.tsx`; their inputs carry the `bare` class so the global `input:not(.bare)` base style doesn't apply.
- Theme: `useTheme()` (`src/lib/theme.ts`, per-device key `theme`: system/light/dark) sets `data-theme` on `<html>`; dark tokens are defined twice in `index.css` (media query guarded by `:not([data-theme=light])`, and `[data-theme=dark]`). An inline script in `index.html` applies the saved theme before React loads.
- First run: `Onboarding` shows until synced key `onboarded` is true. `ReadinessSheet` (sleep/soreness/pain → green/yellow/red, logged in `readiness`) gates starting a workout or run; yellow starts the workout player in `light` mode (−1 set). Strength stats/PRs: `src/lib/strength.ts` (Epley e1RM). Food log: `FoodLog` writes `foodLog` (per date, trimmed to 60 days); it searches `logFoods` (all dishes/foods in `nutrition.ts` via `searchFoods`) plus previously logged custom items (search accepts in-order letters because Thai has no word spaces), shows recently eaten items as chips, "same as yesterday", and saved meal sets (synced `mealSets`). GPX import: `src/lib/gpx.ts`.
- Offline: `public/sw.js` (registered in production only) caches the shell; `sync.ts` persists unsent keys in `pendingKeys`, flushes them before pulling, serializes flushes, and, when the device already belongs to the user (`owner` key), opens immediately from local data and syncs in the background (no spinner on slow/no network); only a first login on a device blocks on the network. Backup/restore JSON is in the avatar menu (`exportData`/`importData`). `sync.ts` and `storage.ts` force a full page reload on HMR because their module state (session user, cache) must be singletons — partial HMR previously broke syncing.
- Safety layer: `src/lib/screening.ts` (ACSM 2015 pre-participation logic, synced `screening`, first onboarding step + `Alerts` banner), `src/lib/weather.ts` (Open-Meteo hourly forecast → shade WBGT via Stull 2011 wet-bulb; levels are conservative ACSM-based tiers; hourly PM2.5 from the Open-Meteo air-quality API → `airLevel` (Thai PCD 2023 bands 25/37.5/75), and `bestHour` avoids worse-air hours; cached 1 h in `heatCache`, versioned `v: 2`), `src/lib/detraining.ts` (gap since last activity → step back 0/1/2 weeks, Mujika & Padilla 2000). `useRunTracker` records screen-off gaps (`gapSeconds`) because browsers suspend GPS when hidden. Long reading sections use `Disclosure`/`Collapse` to keep screens compact.
- Analytics (`src/lib/analysis.ts`, pure, tested): `paceSeries` (rolling ~250 m), `splitAnalysis` (negative/even/positive + CV), `bestEffort`/`personalBests` (fastest 1K…marathon inside any run; needs `Run.times` = cumulative moving seconds aligned with `route`, recorded by the GPS tracker and GPX import), `trainingLoad` (session-RPE × minutes → 42-day/7-day EWMA fitness/fatigue, form = difference; seeded with the first 2 weeks' mean to avoid warm-up bias; `formLabel` is a coaching heuristic, no injury prediction). RPE is asked after runs (`RunDetail`) and workouts (`WorkoutPlayer`); missing RPE falls back to per-kind defaults. Pure coordinate math lives in `src/lib/geo.ts` so tests don't pull in Capacitor/window.
- Guided runs: quality days carry `Day.guide` (`Step[]`, built by `guides.*` in `src/lib/guide.ts` from the same strings as the program tables — `guide.test.ts` asserts every tempo/interval day parses). `GuideRunner` (pure) advances steps by time (clock runs except during manual pause, so standing still in a recovery still counts) or GPS distance; `useGuide` feeds it from `useRunTracker({ onTick })` (called from the GPS callback and the 1 s clock, so cues work with the screen off), speaks via `voice.ts` and persists to local key `activeGuide`. It applies only when the chosen run kind matches today's plan.
- Race goals & journey: synced `goals.race` holds goal seconds per `RaceKey` (`useRaceGoals`), compared with predictions in `PaceCard`; `journey()` in `goals.ts` clears levels (5 km → 10K → half → full) by the longest run, shown by `JourneyCard` on the runs start view. Choosing run kind "race" on a non-race day runs the guided 5K time trial (`guides.timeTrial`), suggested when the prediction source is >6 weeks old. Race days in the plan show `RacePlan` (`src/lib/racePlan.ts`: first 2 km 8 s/km slower, then compensating pace; split times; gels for races >1 h) and a synced `raceChecklist`. `Alerts` warns on ≥2 pain answers in 7 days (`recentPainDays`); the readiness sheet optionally records pain `areas` (`PAIN_AREAS` in `readiness.ts`, each with what to avoid) and `repeatedPainAreas` makes the alert area-specific. Leg tests (`src/lib/legTests.ts`, synced `legTests`, card in progress → fitness): single-leg hop LSI ≥90% and single-leg calf raises ≥25.
- Route heatmap: `heatmapRoutes` (`matched.ts`, routes starting within 30 km of the latest run) drawn by lazy `RouteHeatmap` (canvas renderer, translucent polylines) on the runs stats view.
- Core/hip circuit: `src/lib/circuit.ts` (pure `buildCircuit`/`circuitAt`, 8 bodyweight stations × 2 rounds, 30 s work / 15 s rest) played by `CircuitPlayer` (plan tab card; wall-clock timer, wake lock, Thai voice per step, skip/pause) and logged as a session with `dayKey: 'circuit'`.
- Cross-training: synced `cross` (`CrossSession`: bike/aquajog/swim/elliptical/other, minutes, RPE) logged in `CrossTrainingCard` (runs → history); `crossAsSession` feeds it into `trainingLoad` (RPE × min) on home/fitness, and the calendar shows it as an active day.
- Training calendar: `TrainingCalendar` (progress → history) uses `monthGrid`/`shiftMonth` (`src/lib/calendar.ts`); planned days come from `useProgram().weekOf(monday)` (race-date countdown incl. pre-start, programStart + repeats, ongoing cycle). Plan check-offs (`done`) without a logged run/session still count as active days (calendar + home strength ring).
- Matched routes: `src/lib/matched.ts` (`sameRoute`: distance within 10% and 12 points sampled evenly by distance within 150 m, so direction matters) feeds `MatchedRuns` in run details.
- Ghost runner: `src/lib/ghost.ts` (pure, tested) — only on the guided 5K time trial (during its 5 km work step, timed by the guide clock; ghost = best 5K or predicted × 0.985) and on planned race days (goal time, else prediction; distance from start, moving time). Even-pace ghost; `Runs` shows `GhostCard` (lead seconds + both positions on a track), speaks the gap each km at +250 m (so it doesn't collide with the split cue), toasts the result on finish. Device key `ghostOn`. The ghost's speed is always shown honestly (no deception — Jones 2016).
- Run extras: guide step changes vibrate (`buzz` in `voice.ts`, `@capacitor/haptics` on native, `navigator.vibrate` on web); finished runs store `guide` = completed work steps (`guideResult`); `WeekCheckCard` (home + plan, synced `weekCheck`) asks easy/ok/hard after the week's training is done or on Sunday, and "hard" offers `repeatWeek()` — synced `repeatWeeks` holds Mondays where the week number doesn't advance (`weekAt`/`attemptOf` in `program.ts`; repeated attempts get slot ids `w3x1`); runs keep `startedAt` and run details export GPX (`toGpx` in `gpx.ts`, `saveGpx` in `gpxFile.ts`).
- Distance-target guides (run-walk days built by `guides.runWalk`, rep count estimated at ~10 min/km): `Runs` calls `guide.complete()` once the run reaches the day's `targetKm`, so faster runners aren't told to keep alternating and the run is stored as finished. With a `raceDate`, `plan()` moves the race-week race to the real weekday (`placeRaceDay`). An unknown stored `program` (synced from a newer app version) falls back to `physique`.
- Pace coach: `src/lib/coach.ts` (pure `PaceCoach`: cue only after the pace stays outside the band for a dwell time, then a cooldown). `useRunTracker`'s `onTick` passes the 30 s pace; `Runs` picks the band — easy band (no faster than the zone-E edge) on easy/long runs and guide warm/recover steps, ±5–6% around the target on work steps, nothing during the first 25 s of a step — and speaks `cueText`. Device key `paceCoach`.
- Goals/badges: `src/lib/goals.ts` (pure) computes month/year stats, week streaks and `BADGES` from runs+sessions every time (badges are never stored, so they follow data edits); synced `goals.monthKm` overrides the default goal derived from the program's weekly km; `useBadgeWatcher` (App root) toasts newly earned badges using synced `badgesSeen` (first run on a device marks existing ones seen silently). UI: `MonthGoalCard` on the home tab → badges + year summary sheet. `WeekSummary` (home) compares last week with that week's plan (km, strength days, average logged protein) and previews this week.
- Photos: `src/lib/photos.ts` compresses to ≤1440 px JPEG and always stores the blob in IndexedDB first (`path: 'local:<id>'`); `syncPhotos()` (after adding, after sync/refresh) uploads pending ones to the private Storage bucket `photos` at `<user id>/<photo id>.jpg` (RLS: own folder only, migration `20261025000000_photos.sql`) and rewrites the path. Metadata lives in synced key `photos` (`kind` progress/run/workout + `refId`). Display prefers the local blob, otherwise downloads via a signed URL and caches it locally. Logout uploads pending photos first, then clears the `blobs` store. `PhotoStrip` is attached to run details and workout history; `ProgressPhotos` (weight tab) compares the first and latest photo.
- `RunTypeCard` (`RunTypes.tsx`) explains each run kind with an animated effort profile; nutrition `targets(profile, isRace)` switches to maintenance calories during half/full programs.
- `WorkoutPlayer` is the guided set-by-set logger with auto rest timer (rest parsed from the exercise's `rest` text); in-progress state lives in local key `activeWorkout`. `src/lib/pace.ts` estimates race times/training paces from the best result in the last 60 days (whole runs ≥3 km or best 5K/10K/half segments inside GPS runs; falls back to older data and flags `stale`): Runs/segments slower than 10:00/km (`MAX_SOURCE_PACE`, walking) are never a fitness source, guided easy runs (run-walk/strides/hills: `kind === 'easy' && guide`) are skipped too (also in `programFit` continuous-run capacity), and an estimate from an easy/long run sets `from.easy` (UI note; the pace coach skips the easy band), and `zoneOf` returns E for paces ≥10:00/km — a walk-jog used to become the 5K reference and label walking as zone R. Riegel k=1.07 up to the half, and Vickers & Vertosick 2016 Model 1 (adds weekly mileage) for the marathon; `predictionTrend` re-runs it per week for the 12-week trend line. `criticalSpeed` fits distance vs time of the best 0.4–5 km efforts in 90 days (Smyth & Muniz-Pumares 2020; needs ≥3 distances incl. ≥3 km) and shows CS plus a 94%-CS first-half marathon pace. It's called with `useMemo` because segment search is O(points).
- Android back button: `src/lib/back.ts` keeps a stack — overlays call `useBackClose(onClose)` (Sheet, run detail, workout player, dialogs, account menu; the active run minimizes instead), and `useBackButton` in `App` falls back to the home tab, then minimizes the app. `Sheet` has an X button and drag-to-close on its header (outer layer animates, inner layer follows the finger, because the `both` fill-mode animation would override an inline transform).
- Full-screen overlays (`Sheet`, `WorkoutPlayer`, active run, run detail) must render through `Portal` from `ui.tsx` — `<main>` animates on tab change, which creates a stacking context that would put the sticky header/bottom nav on top of them. Cross-tab navigation uses `useNav()` (`src/lib/nav.ts`).
- Motion: keyframes/`animate-*` tokens and the `stagger` utility are in `src/index.css` (also `animate-ring` for the home rings and `.route-draw` for finished-run polylines, which need `pathLength=1` set on the Leaflet path; `useCountUp` animates run-detail numbers); all buttons get a press-scale globally; everything is disabled under `prefers-reduced-motion`.
- Exercise demo images: `src/data/demos.ts` maps exercise names (library + workouts) to free-exercise-db ids; images live in `public/exercises/<id>-0|1.jpg` (resized to 360 px) and `ExerciseDemo` crossfades start/end frames (static pair under reduced motion). Exercises without a usable photo get a two-pose line drawing from `src/data/stickDemos.ts` (side view, viewBox 120×80, floor at y=72). `sw.js` caches `/exercises/` cache-first. A test checks every mapped file exists.
- `src/data/muscles.ts`: maps exercise **name** (must match `workouts.ts` exactly) → primary/secondary muscles; drives `BodyMap` (hand-drawn SVG, left half mirrored) and weekly set counts. Renaming an exercise requires updating this map.
- `src/lib/storage.ts`: `usePersisted(key, initial)` — a `useSyncExternalStore`-backed in-memory store persisted to IndexedDB (`src/lib/idb.ts`, db `exercise-plan`, stores `kv` and `blobs`; falls back to localStorage when IndexedDB is unavailable, e.g. in vitest). `main.tsx` awaits `initStorage()` before dynamically importing the app because reads are synchronous from the cache and modules like `sync.ts` read at import time. `initStorage` moves any leftover localStorage keys into IndexedDB (except `LOCAL_ONLY`: Supabase `sb-*`, `activeRun`, `activeGuide`, `heatCache`, `localMode`, `lastBackup`) and keeps `theme` mirrored in localStorage for the inline script in `index.html`. It is shared across all components using the same key (so multiple day cards writing `sessions` don't clobber each other). Prefer functional updates `set(prev => ...)`. Keys: `tab`, `profile`, `mode`, `week`, `done` (`${mode}-w${week}-${day.key}`), `sessions`, `runs`, `log`. Changing a data shape or a `Day.key` silently orphans stored data.
- Auth/sync: `AuthGate` (wraps `App`) shows `Login` until there's a session (or renders the app with `session = null` in local mode), then awaits `startSync` before rendering. Backups (`src/lib/backup.ts`) include local-only photo blobs as base64; native saves via the share sheet; local mode shows a reminder every 14 days (`lastBackup`). `src/lib/sync.ts` mirrors the `SYNCED_KEYS` of the persisted store into table `public.user_data` (one jsonb row per user+key, RLS own-rows-only; schema in `supabase/migrations/`). Writes are debounced upserts (a `null` value deletes the row instead — `value` is NOT NULL and one null row fails the whole batch); on login/refocus the server copy replaces local (server is source of truth). Only the first login on a device with no `owner` key merges pre-existing local data up. Logout: `stopSync` flushes (asks if unsent), then `signOut` (falls back to `scope: 'local'` offline), and only then `clearSyncedData()` — clearing first made the still-mounted app show onboarding while signOut was pending. Adding a new persisted key that should sync = add it to `SYNCED_KEYS`.
- `src/lib/log.ts`: `Session` (logged sets per exercise) and `Run` types + formatters; `lastSetsFor` shows previous numbers for progressive overload.
- Browsers stop GPS when the screen locks/app backgrounds; that limitation is stated in the UI. Geolocation needs HTTPS (fine on Vercel and localhost).
- `src/lib/date.ts`: local-time date strings (`YYYY-MM-DD`) and Monday-based `weekStart`; don't use `toISOString()` for dates (UTC shifts the day in Thailand).
- Tabs are deep-linkable via hash (`/#plan`, `/#runs`, ...), handy for headless screenshots: `google-chrome-stable --headless=new --window-size=390,1500 --screenshot=out.png http://localhost:4173/#runs` after `npx vite preview` (the app is login-gated, so screenshots of inner tabs need a temporary bypass of `AuthGate`).
- Styling: Tailwind v4 via `@tailwindcss/vite` (no config file). Colors are semantic tokens (`bg-card`, `text-muted`, `bg-accent`, `ring-line`, `text-run`, …) defined as CSS vars in `src/index.css` and mapped with `@theme inline`; dark mode only redefines the vars — never use raw palette colors like `bg-gray-100`. Shared primitives (`Card`, `Button`, `Stat`, `Badge`, `Segmented`, `Meter`, `Field`) live in `src/components/ui.tsx`; `cx` in `src/lib/cx.ts`. Layout is a centered phone-width column (`max-w-lg`) with a fixed 5-tab bottom nav on all screen sizes; Sources is reached from the avatar menu.
- Storage size: all runs (with routes) live in the single `runs` key, and localStorage holds ~5 MB, so route points are stored rounded to 5 decimals (`roundPoint` in `geo.ts`, ~1 m); `useCompactRuns` (App root) migrates older full-precision routes, and `storage.ts` toasts once on a quota error. If data keeps growing, move routes out of `runs` (e.g. IndexedDB + a separate table).
- Runs tab has sub-views (device key `runsView`: start / history / stats). `RunHistory` groups by month (3 months per page, kind filter, `RoutePreview` thumbnails); dates in lists use `niceDate`/`monthLabel` from `date.ts`.
- Error reporting (instead of Sentry): `src/lib/errors.ts` keeps the last 30 errors in the device key `errorLog` (window `error`/`unhandledrejection` handlers installed in `main.tsx` after storage init, plus `ErrorBoundary` around the app) and uploads unsent ones to `public.app_errors` (RLS own rows, migration `20261026000000_app_errors.sql`) when logged in, after each sync. Viewable via account menu → ปัญหาที่พบ.
- Run events: `useRunTracker({ onEvent })` emits `autopause`/`resume` (status transitions inside `update`) and `gpsLost`/`gpsBack` (no fix for 20 s while tracking; `signalLost` drives the banner, which takes priority over the auto-pause banner). `Runs` speaks them when voice is on.
- GPS distance filter: `src/lib/track.ts` `TrackFilter` (tested by simulation in `track.test.ts`, including walking and run-walk): moving = EMA speed ≥0.6 m/s; distance is only discarded after ≥5 s continuously below that (a single slow fix used to reset the anchor and lost ~30% of walking distance before v2.26); anchors every 26 m. `remeasure` (`analysis.ts`) recomputes km + splits from a stored route for older runs (button in run details).
- Runs: `useRunTracker` in `src/lib/gps.ts` (Kalman-smoothed GPS, auto-pause, per-km splits, in-progress run persisted to localStorage key `activeRun` and restored as paused). `RunMap` (Leaflet) is lazy-loaded so the map library is a separate chunk.

## Versioning

Semver `x.y.z` in `package.json` (y = feature, z = fix). Vite injects it as `__APP_VERSION__` (`APP_VERSION` in `src/lib/update.ts`, shown at the bottom of the avatar menu) and writes it into `/version.json`; `android/app/build.gradle` reads it for `versionName` and `versionCode = x*10000 + y*100 + z`. With each commit-and-push of a feature/fix: bump the version, add a `CHANGELOG.md` entry (Thai, newest first), and push an annotated tag `vX.Y.Z`.
