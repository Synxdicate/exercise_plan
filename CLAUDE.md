# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal, Thai-language workout + nutrition planner (Vite + React 19 + TypeScript + Tailwind CSS v4, no router, `lucide-react` icons, Leaflet/OpenStreetMap for run maps). It's a static SPA deployed to Vercel (`vercel.json`, output `dist/`). Auth and cross-device sync use Supabase (Google + email/password); the app is login-gated.

Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` in `.env.local` (see `.env.example`) and in Vercel project env vars. `src/lib/supabase.ts` throws at startup if missing.

The owner: male, 20 y/o, 165 cm, 64.5 kg, currently jogs 2.5–5 km 2–3×/week, lives in Thailand, goal is a lean athletic "Tom Holland" physique, trains at a gym or a public park. These are the defaults in `src/lib/calc.ts`.

## Commands

- `npm run dev` — dev server
- `npm run build` — `tsc -b` type-check then `vite build`
- `npm test` — vitest (`src/lib/__tests__/`); single file: `npx vitest run src/lib/__tests__/programs.test.ts`. Tests cover pure logic only (calc, programs safety properties like ≤20% weekly volume jumps and taper, progression, pace, GPX parsing, merge, dates).
- `npm run lint` — oxlint

## Android app (Capacitor)

`android/` is a Capacitor 8 project (`capacitor.config.ts`, appId `com.synxdicate.exerciseplan`) wrapping the same `dist/` build for personal sideloading. `npm run android:apk` builds web + syncs + `gradlew assembleDebug` (needs JDK 21 and an Android SDK with `ANDROID_HOME` set); `npm run android:install` installs via adb. `src/lib/native.ts` exposes `isNative`, `SITE_URL` (email links must point to the Vercel site, not `https://localhost`) and the `BackgroundGeolocation` plugin; `useRunTracker` uses it on native so GPS keeps recording with the screen off (foreground-service notification), and skips the web screen-off gap logic. Google sign-in is hidden on native (Google blocks OAuth inside WebViews; would need a deep-link + external browser flow). The service worker is only registered on the web.

## Architecture

- `src/data/*.ts` holds **all content** (exercises, weekly schedules, foods, YouTube channels, references). Components only render it. Content edits go here, not in components.
  - `workouts.ts`: `gymWeek` and `parkWeek` are parallel 7-day `Day[]` arrays (shared run/rest days). `phases` describes the 12-week periodization (week 9 = deload, handled specially in `Plan.tsx`). Each exercise's `video` field is a YouTube *search query*, turned into a link via `yt()`.
  - `nutrition.ts`: approximate kcal/protein values (USDA / labels / commonly published Thai single-dish values).
  - `sources.ts`: YouTube channels and research references shown on the Sources tab.
- `src/lib/calc.ts`: Mifflin-St Jeor BMR × activity → TDEE, plus goal delta → macro targets (protein 2.0 g/kg, or 1.8 on lean bulk; fat 0.9 g/kg; carbs fill the rest). Shared by Overview and Nutrition tabs via the `profile` state in `App.tsx`.
- Programs: `src/data/programs.ts` defines `physique` (12 wk, reuses `gymWeek`/`parkWeek`), `ten` (10K, 10 wk), `half` (16 wk) and `full` (18 wk). Race programs are generated per week from the `tenWeeks`/`halfWeeks`/`fullWeeks` tables (`easyB: 0` turns Saturday into a rest day) (easy/quality/easy/long km, cutbacks, taper) plus 2 runner strength days per mode. `useProgram()` (`src/lib/program.ts`) is the single source for the current program, mode, week and plan; with a `raceDate` the current week is computed backwards from race week, otherwise it's the manual `week` key. Gym vs park is chosen per weekday slot: the `mode` key holds the preference (`gym`/`park`/`mix` — mix sends the week's last strength day to the park), `dayLocation` holds per-day overrides, and `weekPlan` swaps in the matching variant (`variants()` returns gym/park 7-day arrays with identical run/rest days). Check-offs use slot ids `${program}-w${week}-d${i}` (i = 0 Monday) so switching location keeps them; `isDone` also reads the older mode+key ids.
- `src/lib/progression.ts` `suggest()` implements double progression for the workout player (all sets at the top of the rep range → +2.5 kg, +5 kg for lower-body lifts). References in `src/data/sources.ts` carry a category and evidence `level`; claims shown in the app should map to one of them (PubMed links were verified via eutils), and media sources are only for describing Tom Holland's training style.
- Forms: use `TextInput` / `NumberInput` (unit suffix, optional `stepper`) / `SelectInput` / `DateInput` from `src/components/Form.tsx`; their inputs carry the `bare` class so the global `input:not(.bare)` base style doesn't apply.
- Theme: `useTheme()` (`src/lib/theme.ts`, per-device key `theme`: system/light/dark) sets `data-theme` on `<html>`; dark tokens are defined twice in `index.css` (media query guarded by `:not([data-theme=light])`, and `[data-theme=dark]`). An inline script in `index.html` applies the saved theme before React loads.
- First run: `Onboarding` shows until synced key `onboarded` is true. `ReadinessSheet` (sleep/soreness/pain → green/yellow/red, logged in `readiness`) gates starting a workout or run; yellow starts the workout player in `light` mode (−1 set). Strength stats/PRs: `src/lib/strength.ts` (Epley e1RM). Food log: `FoodLog` writes `foodLog` (per date, trimmed to 60 days). GPX import: `src/lib/gpx.ts`.
- Offline: `public/sw.js` (registered in production only) caches the shell; `sync.ts` persists unsent keys in `pendingKeys`, flushes them before pulling, serializes flushes, and lets the app start offline if the device already belongs to the user. Backup/restore JSON is in the avatar menu (`exportData`/`importData`). `sync.ts` and `storage.ts` force a full page reload on HMR because their module state (session user, cache) must be singletons — partial HMR previously broke syncing.
- Safety layer: `src/lib/screening.ts` (ACSM 2015 pre-participation logic, synced `screening`, first onboarding step + `Alerts` banner), `src/lib/weather.ts` (Open-Meteo hourly forecast → shade WBGT via Stull 2011 wet-bulb; levels are conservative ACSM-based tiers, cached 1 h in `heatCache`), `src/lib/detraining.ts` (gap since last activity → step back 0/1/2 weeks, Mujika & Padilla 2000). `useRunTracker` records screen-off gaps (`gapSeconds`) because browsers suspend GPS when hidden. Long reading sections use `Disclosure`/`Collapse` to keep screens compact.
- Analytics (`src/lib/analysis.ts`, pure, tested): `paceSeries` (rolling ~250 m), `splitAnalysis` (negative/even/positive + CV), `bestEffort`/`personalBests` (fastest 1K…marathon inside any run; needs `Run.times` = cumulative moving seconds aligned with `route`, recorded by the GPS tracker and GPX import), `trainingLoad` (session-RPE × minutes → 42-day/7-day EWMA fitness/fatigue, form = difference; seeded with the first 2 weeks' mean to avoid warm-up bias; `formLabel` is a coaching heuristic, no injury prediction). RPE is asked after runs (`RunDetail`) and workouts (`WorkoutPlayer`); missing RPE falls back to per-kind defaults. Pure coordinate math lives in `src/lib/geo.ts` so tests don't pull in Capacitor/window.
- `RunTypeCard` (`RunTypes.tsx`) explains each run kind with an animated effort profile; nutrition `targets(profile, isRace)` switches to maintenance calories during half/full programs.
- `WorkoutPlayer` is the guided set-by-set logger with auto rest timer (rest parsed from the exercise's `rest` text); in-progress state lives in local key `activeWorkout`. `src/lib/pace.ts` estimates training paces/race times from the best logged run via Riegel.
- Full-screen overlays (`Sheet`, `WorkoutPlayer`, active run, run detail) must render through `Portal` from `ui.tsx` — `<main>` animates on tab change, which creates a stacking context that would put the sticky header/bottom nav on top of them. Cross-tab navigation uses `useNav()` (`src/lib/nav.ts`).
- Motion: keyframes/`animate-*` tokens and the `stagger` utility are in `src/index.css`; all buttons get a press-scale globally; everything is disabled under `prefers-reduced-motion`.
- `src/data/muscles.ts`: maps exercise **name** (must match `workouts.ts` exactly) → primary/secondary muscles; drives `BodyMap` (hand-drawn SVG, left half mirrored) and weekly set counts. Renaming an exercise requires updating this map.
- `src/lib/storage.ts`: `usePersisted(key, initial)` — a `useSyncExternalStore`-backed store over localStorage, shared across all components using the same key (so multiple day cards writing `sessions` don't clobber each other). Prefer functional updates `set(prev => ...)`. Keys: `tab`, `profile`, `mode`, `week`, `done` (`${mode}-w${week}-${day.key}`), `sessions`, `runs`, `log`. Changing a data shape or a `Day.key` silently orphans stored data.
- Auth/sync: `AuthGate` (wraps `App`) shows `Login` until there's a session, then awaits `startSync` before rendering. `src/lib/sync.ts` mirrors the `SYNCED_KEYS` of the persisted store into table `public.user_data` (one jsonb row per user+key, RLS own-rows-only; schema in `supabase/migrations/`). Writes are debounced upserts; on login/refocus the server copy replaces local (server is source of truth). Only the first login on a device with no `owner` key merges pre-existing local data up. Logout flushes then clears synced keys. Adding a new persisted key that should sync = add it to `SYNCED_KEYS`.
- `src/lib/log.ts`: `Session` (logged sets per exercise) and `Run` types + formatters; `lastSetsFor` shows previous numbers for progressive overload.
- Browsers stop GPS when the screen locks/app backgrounds; that limitation is stated in the UI. Geolocation needs HTTPS (fine on Vercel and localhost).
- `src/lib/date.ts`: local-time date strings (`YYYY-MM-DD`) and Monday-based `weekStart`; don't use `toISOString()` for dates (UTC shifts the day in Thailand).
- Tabs are deep-linkable via hash (`/#plan`, `/#runs`, ...), handy for headless screenshots: `google-chrome-stable --headless=new --window-size=390,1500 --screenshot=out.png http://localhost:4173/#runs` after `npx vite preview` (the app is login-gated, so screenshots of inner tabs need a temporary bypass of `AuthGate`).
- Styling: Tailwind v4 via `@tailwindcss/vite` (no config file). Colors are semantic tokens (`bg-card`, `text-muted`, `bg-accent`, `ring-line`, `text-run`, …) defined as CSS vars in `src/index.css` and mapped with `@theme inline`; dark mode only redefines the vars — never use raw palette colors like `bg-gray-100`. Shared primitives (`Card`, `Button`, `Stat`, `Badge`, `Segmented`, `Meter`, `Field`) live in `src/components/ui.tsx`; `cx` in `src/lib/cx.ts`. Layout is a centered phone-width column (`max-w-lg`) with a fixed 5-tab bottom nav on all screen sizes; Sources is reached from the avatar menu.
- Runs: `useRunTracker` in `src/lib/gps.ts` (Kalman-smoothed GPS, auto-pause, per-km splits, in-progress run persisted to localStorage key `activeRun` and restored as paused). `RunMap` (Leaflet) is lazy-loaded so the map library is a separate chunk.

## Content rules

- Keep training/nutrition claims evidence-based and realistic; cite new claims in `sources.ts`. Never invent specific YouTube video URLs/IDs — use channel URLs that are known to exist or `yt()` search links.
- UI text is Thai; exercise names stay in English with a Thai description.
- Icons come from `lucide-react`; no emoji in the UI.
